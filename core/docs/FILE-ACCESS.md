# 共享空间：完整本地副本与多设备同步

2026-11-19 用户选择完整同步，覆盖此前“唯一写入设备”的方案。目标是在 NAS 选择共享空间，再选择设备上的本地位置；文件离线可读写，联网且同步开启后交换更新。不采用按需下载，也不把 SMB 挂载当作离线副本。

## 当前配置

- 共享空间“共享”：NAS 的 `data/shared/`，Syncthing Folder ID 为 `nas-shared`。
- 多设备双向完整同步；Mac 建议存放于 `~/NAS/共享`，首次接入由用户选择，也可添加至访达侧边栏。
- 原 SMB `nas` 与网页入口继续只读，作为在线浏览；独占 SMB 写入口与 Meta 授权按钮已停用，私人 TCP 1446 路由已移除。
- 仅同步普通文件；数据库、Immich、Git 裸仓库、配置和密钥不进入此空间。所有已在 shared 中的用户文件保留，未清空或重建。
- Syncthing 传输通过私人 Tailscale TCP 22000，地址为 `tcp://<你的 NAS Tailscale 域名>:22000`；不开放公网，不启用 Funnel。NAS 全局/局域网发现、中继和 NAT 穿透已关闭。客户端需明确填写 NAS 连接地址。
- NAS 每个文件保留最近 **20 个收到的旧版本**（Simple versioning，不按天自动过期）；第 21 个以上的最旧版本会被清理。版本存于 shared/.stversions，纳入现有一致性备份。
- 同时离线修改同一文件，保留 `sync-conflict` 副本，**不自动删除冲突副本**（maxConflicts=-1）。Meta 展示冲突数和文件名，需要用户选择、合并及清理。没有通用二进制文件自动合并能力。

版本保护针对从其他设备收到的覆盖/删除；尚未同步的连续本地编辑不等于每次保存都有 NAS 历史。单纯删除会传播到所有同步设备；同步不是独立备份。应用内部历史或客户端版本保护可以另外启用。同步跨越 Windows/macOS 文件系统，不要仅靠大小写区分文件名；不建议把数据库或多文件事务应用的数据目录直接同步。

## 网页自助接入（Mac / Windows）

1. 安装并启动 [Syncthing](https://syncthing.net/downloads/)，连接 Tailscale，然后在需要接入的电脑浏览器打开 Meta。
2. 在“多设备文件访问 → 连接此设备”中，按链接打开本机 Syncthing，复制“操作 → 设置 → 常规”的 API Key，填入“本机授权码”，点击“授权并继续”。浏览器请求本机网络权限时允许；自定义端口在高级选项中填写，默认 8384。
3. Meta 自动读取本机设备 ID 和已有共享，填好本地存放位置（默认本机用户目录下 NAS/共享）。尚未绑定时确认或修改路径，点击“绑定共享空间”。已绑定时只显示路径文字，不显示路径输入框和绑定按钮。双方设备登记、NAS 地址、共享 ID、目录授权均自动配置。
4. 完成后 Syncthing 在后台运行，网页可以关闭。现有兼容共享复用原路径，不移动或重新下载文件。新的位置必须是尚未建立的专用目录，由 Syncthing 自动创建（原 API 只能列目录，不能可靠判断已有目录是否为空），不接受与其他同步任务重叠的位置、用户主目录或网络挂载；外接盘位于 /Volumes 下的情况当前也不自动接入。

用户首次仍需从本机 Syncthing 复制 API Key，原软件没有面向 Meta 的一键 OAuth 授权接口。API Key 具有本机同步管理权限，仅在当前页面内存使用，不上传 NAS，不放入 URL、localStorage 或 sessionStorage；清除授权、退出 Meta 或关闭页面后不保留。刷新后如需再次管理本机，要重新授权；已配置的后台同步不受影响。Meta 请求本机 API 固定使用 `http://127.0.0.1:<端口>`，不带浏览器 Cookie、不跟随重定向；发往 NAS 的登记只包含公开设备 ID 和名称。

新建本地共享先保持暂停，NAS 登记成功后才开启；失败不自动删除本机设备或共享。部分失败后显示现有共享和解绑入口，可解绑保留文件后重新绑定。若刷新后发现暂停、不同路径/策略或同 ID 实际属于其他 NAS，拒绝自动接管，提示用户核实。不会因用户输入一个新路径而迁移已有同步目录。

浏览器对 HTTPS 页面访问 loopback 的权限与实现各有差异。已验证 Windows Chrome 在 loopback Meta 来源下的真实跨域认证，以及真实 Syncthing 的配置写入；Mac 的私人 HTTPS Meta 来源和权限弹窗仍需实机验证。不会要求关闭浏览器安全检查或公开本机 Syncthing API。

### 手动接入备用

仅当浏览器兼容性阻止直连时，使用 Syncthing 原界面添加 NAS 设备与文件夹。NAS ID 为 `<从管理页获取的 NAS 设备 ID>`，地址 `tcp://<你的 NAS Tailscale 域名>:22000`，Folder ID `nas-shared`，类型“发送与接收”。本机 ID 由管理员在 NAS 端登记。原手工复制流程不再是主要入口。

## 当前验收边界

用户已确认 Mac 的本地文件同步到 NAS；NAS 已确认对端连接、无错误、无待同步项。新的网页自动接入流程尚待 Mac 实机验证。公司 VPN 共存未通过：REDpass 与 Tailscale 仍需切换，但公司 VPN 开启期间可照常编辑本地副本，稍后连接 Tailscale 再同步。

隔离实验使用两个真实 Syncthing 进程，在无公网连接的独立网络内验证离线编辑、冲突双副本、删除传播、版本保留和恢复后重新同步。证据为 `system/runtime/acceptance/full-sync.json`，不等于 macOS 实机验收。Meta 暂停/恢复、错误设备 ID 拒绝、独占写授权停用证据为 `full-sync-control.json`。原网页认证、只读和管理面板渲染继续复验。

## 部署与恢复

新路径、文件夹和传输声明位于 Compose 与 `nas_sync.py`。显式迁移入口为 `configure-sync.py --apply`：先停止 nas-agent，保存配置及路由副本、撤销旧写入后端、移除旧写路由、更新模式、启动 Syncthing 并创建受保护的共享空间，之后启动 nas-agent。它拒绝覆盖其他已有同步文件夹。重跑初始化/prepare 不会重新生成已存在的设备身份；prepare 只接受已识别的受保护共享声明。

恢复保留 Syncthing 配置、证书与私钥；索引可从内容重新扫描。恢复到旧时间点时不要直接向其他设备传播旧数据或删除：先暂停同步，核对双方文件和恢复方向，再明确恢复。

旧的独占 SMB 写入设计和验收保存在 [历史记录](FILE-ACCESS-SMB-HISTORY-2026-11-19.md)，不作为当前使用说明。

依据：[冲突处理](https://docs.syncthing.net/users/syncing.html)、[版本保留的适用范围](https://docs.syncthing.net/users/versioning.html)、[配置 API](https://docs.syncthing.net/rest/config.html)。

## 更换本机存放位置（2026-11-20）

已绑定设备在授权后显示只读路径与“解除本机绑定”，不提供路径输入框。需要换位置时先解绑：先暂停本机该共享，再移除 NAS 共享中的本机成员关系，最后 DELETE 本机该文件夹的同步配置。保留双方文件、全局设备身份和其他同步任务，不删除用户内容。解绑成功后才显示新路径输入框，填写尚未建立的新目录重新绑定。

此操作不是文件搬迁：旧目录保留，未同步修改也留在旧目录，不会自动搬入新位置。中途失败保持暂停，保留配置方便重试；重复撤销 NAS 成员关系是幂等的。控制 API 拒绝解除 NAS 自身；界面不自动接管同 ID 但属于其他 NAS 的目录。

验收增加：已绑定/未绑定 DOM 状态切换；失败解绑不删除配置；成功解绑顺序；真实 Syncthing 删除共享配置后实际测试文件内容保持；其他 NAS 成员不受影响；已部署 API 拒绝 NAS 自身撤销。未对用户 Mac 实际执行解绑，既有同步保持。


2026-11-20 路径错误反馈修正：绑定校验失败后的状态刷新不再把用户路径重置为默认目录。只有首次授权初始化默认路径；错误以红色“绑定未完成”显示并滚动到提示处，原输入保留。回归覆盖：已有目标目录被拒绝、输入不变、错误可见、不写入配置，前端行为共 11 项通过。


## 进度、冲突与恢复副本（2026-11-21）

进度依据 Syncthing 已知索引：NAS 接收进度与每台设备接收进度分开显示。离线设备可能仍有未上报的本地修改，显示“当前进度未知”；有待接收项时百分比不会四舍五入成 100%。冲突入口提供当前文件与冲突副本的只读链接，由用户在本机比较、合并和决定删除。

历史版本通过 Syncthing 官方 API 读取，页面最多展示最近 500 个。选择“恢复为新副本”后，文件发布到 shared/Recovered-时间-随机编号/原相对路径，当前文件和 .stversions 内源版本保持。暂存位于同步目录外，发布前校验卷、空间、版本存在性、文件类型/大小，拒绝路径逃逸与链接。恢复期间 NAS 共享暂停，成功只恢复原先开启的状态，失败会明确提示；其他设备不会被远程擅自修改暂停设置。

验收：sync-recovery.json（实际文件操作和安全保护）、sync-history-api.json（真实 Syncthing 版本目录与恢复副本）、connect-js.json（进度与冲突链接）、生产鉴权和错误版本拒绝。没有对用户现有文件执行恢复；Mac/Windows 大文件恢复及双实机交接仍需进一步验收。
