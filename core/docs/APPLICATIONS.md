# 零号庭院 · Garden Zero：应用、功能与系统监控

管理台按应用管理能力，容器实施细节由宿主控制器处理。内部 Docker 服务名、项目名与地址不变。

## 应用与功能

应用列表每项占整行。折叠时展示图标、名称、用途摘要、运行状态及打开/日志入口；说明合并到折叠行，点击展开显示子功能、目录权限和专用设置；启停说明通过状态按钮的悬停/键盘焦点提示查看。操作列固定对齐，不支持的网页入口保留灰色按钮。定时刷新保留展开状态、共享绑定表单节点及未提交路径。

| 应用 | 能力 | 系统页对应容器 |
| --- | --- | --- |
| Immich 相册 | 照片与视频备份；可选智能检索与人脸识别 | immich-server、database、cache、immich-machine-learning |
| 文件浏览 | 网页浏览/下载、SMB 只读挂载 | files、smb |
| 共享同步盘 | 完整副本、连接本机、暂停共享、进度、冲突、历史恢复 | syncthing |
| 私人知识库 | 只读 Markdown 和附件 | knowledge |
| Git 仓库 | 授权 SSH 推送与拉取 | git |
| 零号庭院基础服务 | 管理、认证及私人远程连接；网页禁止关闭 | meta、tailscale |

原“多设备共享空间”合并至共享同步盘的展开区域，不再另设服务区。智能检索是相册的功能，不作为独立应用：相册关闭会同时停用它；功能设置保留，相册重开时恢复。相册未运行或未就绪时不能单独开启智能检索，后端同样校验，旧模块启动接口也不能绕过。单独切换智能检索不重启相册、数据库或缓存。

前端通过 `app-power`（app、enabled）与 `app-feature`（app、feature、enabled）操作逻辑应用与功能；后端返回功能可用性、保存设置及当前运行状态。前端不决定功能使用哪个容器、是否修改配置。目录权限和底层细节通过独立的系统入口查看。

## 日志与系统监控

- 左侧“日志”进入同一工作台布局的日志页面，通过应用下拉框选择应用，使用上方标签切换“全部日志”或单个来源（相册、智能检索、数据库、缓存等）。切换期间忽略旧请求的响应，防止日志串台；标签支持方向键、Home/End。应用行的日志图标仍可打开独立窗口，也支持从系统表格查看单个容器。`/logs?app=immich` 聚合该应用日志，`/logs?service=database` 查看指定 NAS 服务。每个容器最近 100 行，总输出最多 64,000 字符；默认手动刷新，可选择每 10 秒刷新。正文以纯文本呈现，未登录不可读取。
- `/system` 展示仅属于 NAS 项目的全部容器：所属应用、状态/健康、本次连续运行时间、CPU、内存工作集/上限、镜像、真实绑定路径及读写模式、累计网络/磁盘 I/O、进程数、重启次数和发布端口。可按应用筛选，表格支持横向滚动；每 10 秒采样刷新，服务端短暂缓存 5 秒。
- 停止或采样失败时，CPU/内存/运行时间显示未知，不将未知当作 0。CPU 可超过 100%（多核）；内存按 Docker 统计口径。接口不返回容器环境变量或凭据内容，不接受任意项目、容器 ID 或命令。

## NAS 资源概览与相册存储

首页四个图形面板展示 NAS 运行环境的累计运行时间、总体 CPU、内存，以及数据 SSD / 本机备份磁盘的空间用量。CPU 与内存为环形使用率图；磁盘为已用/总量容量条；运行时间配时钟与每天一格的累计刻度。移动端按两列排列。旧的就绪应用数、共享文件数、SSD 剩余数字及备份日期面板不再占用这一区域。

运行时间来自 /proc/uptime；CPU 由 /proc/stat 的采样差值计算，总体范围 0—100%，guest 不重复计数；内存按 MemTotal - MemAvailable 计算。统计范围为承载 NAS 的 WSL/Linux 运行环境，含同环境其他进程，页面提供范围说明；不会将容器内存上限相加冒充总内存。磁盘为所在卷整体用量，包含其他文件。采样失败保持未知，不伪装为 0。没有修改主机资源设置。

数据库文件系统与稀疏镜像属于 Immich，移到相册展开区域，分别显示文件系统用量与镜像实际分配/上限。通用磁盘区仅保留数据 SSD 和备份磁盘。图库、同步目录和内部服务 ID 不因界面名称变更而迁移。

## 状态保存

网页登录、退出、刷新均不执行启停。明确选择原子保存到 `C:\nas\system\state\desired-modules.json`，主机启动恢复保存的选择；移除自动启动勾选及其旧写接口。正常 systemd 退出使用 `nasctl.py shutdown`，不覆盖用户选择；备份和存储保护的临时停止同样保留选择。底层 Docker restart=no，启动仍需通过卷身份、容量、数据库和目录权限检查。

正常整机重启仍依赖 Windows 登录任务、WSL 与磁盘就绪，本次不自动重启共享 WSL 或物理主机。

## 每个 data 路径的权限

规则源为 `core/templates/data-access.json`，部署到 `C:\nas\system\installed\data-access.json`。最长路径优先，递归覆盖所有当前、新增目录与文件。未分配目录没有应用写入者。规则是 NAS 容器数据挂载边界，不是限制 Windows/WSL 宿主机管理员的文件 ACL。

| data 路径（递归） | 唯一常规写入者 | 额外只读者 |
| --- | --- | --- |
| immich | immich-server | 无 |
| git | git | 无 |
| shared | syncthing | 无 |
| knowledge | 主机管理员 | knowledge |
| 其他未登记路径 | 尚未分配 | 无 |

shared 内部的历史版本与目录标记继承同一条规则，不单独拆分展示。inbox 已不存在，规则及新环境初始化均不再创建它。用户界面使用不含 data/ 的相对路径。

上述所有路径都允许文件浏览、SMB 和一致性备份读取；写入者本身也可读取。知识库网页没有编辑能力，源文件当前由主机管理员维护。机器学习、数据库和平台服务没有 data 挂载；数据库和模型缓存位于 C 盘独立位置。

shared 的唯一 NAS 常规写入服务是 Syncthing，不限制已绑定客户端多设备编辑。冲突保留双方版本，由用户合并。历史恢复控制器是明确登记的维护例外：取得生命周期锁、暂停 NAS 共享后生成新副本，不覆盖当前文件；无该维护授权则拒绝恢复。

应用行展示合并说明，展开显示功能与目录权限；状态按钮提示启停方式，实际容器单独在系统监控中查看。存储区展示完整规则，提供任意相对路径的继承查询。控制器每次启动前检查实际 Compose 绑定：拒绝错误写入者、越权读取、跨所有者的可写父目录和链接挂载；状态接口对现存 Docker 容器挂载再次核对并报告差异。宿主机管理员仍可维护文件；未实现每个 tailnet 成员的独立文件 ACL。
