# 原生 Btrfs 数据卷迁移

用户已选择原生 Btrfs 并授权迁移。实际卷 UUID、USB 实例、分区标识、备份清单与操作结果只保存于 system 私有运行目录；本文不包含可直接格式化某台机器的固定设备命令。

## 目标布局

- 项目代码与 Git 仓库迁到 `C:\nas`，core 与 system 仍分开，Windows 启动入口不依赖消失的 NTFS 数据盘盘符。旧 host 运行目录或兼容链接继续忽略，不提交。
- 用户文件迁入 SSD 原生 Btrfs 数据分区的 `data` 子卷，顶层受控挂载为 `/run/nas/storage`，应用数据根为 `/run/nas/storage/data`。应用 ID、相对目录与内容保持不变。
- 共享数据库与当前镜像位置不变，继续受原 UUID、loop 来源和只读检查保护；不重新初始化数据库或账号。
- 只处理已核验的原 NAS NTFS 数据分区，不重建整盘分区表，不修改系统盘、备份盘或其他分区。原生盘接入后 Windows 不再直接以原盘符访问用户文件。

## 必须按顺序完成

1. 核对源卷、目标备份卷及各自物理盘，确认备份目标是另一块盘、空间足够且目录不是重解析点。
2. 将全部用户数据、Git 和代码预复制到独立迁移目录；保留已有签名镜像备份目录不动。运行时目录联接不能跟随复制整个活动系统。
3. 代码完成检查、提交和推送。代码更新后必须补齐迁移副本，不能因预复制开始时间较早而遗漏新文件。
4. 准备一次性 Windows USBIPD 安装与共享，核验官方安装包哈希及签名。只共享已核验的 NAS USB 实例，不用强制绑定，不在此步骤 attach、卸盘或格式化。入站规则只允许 WSL 虚拟接口，不开放 LAN USB 访问。该阶段需要 Windows 管理员，日常 attach 不需要。
5. 安排切换窗口：保存实际应用选择，暂停云盘自动任务并安全结束其活动任务；按注册资源声明停止持久数据写入者，锁定生命周期，进行最终差异复制和逐文件哈希核对。
6. 正式导出所有已登记数据库、角色及配置/SQLite；备份在受保护的外部迁移目录，不在 C 盘生成完整用户数据副本。数据库备份须校验并验证可读取/恢复，保护恢复所需凭据。
7. 在所有最终校验通过后生成离盘可信检查点，完整受控停机；代码和操作入口已独立于源盘。正常解除原 NTFS 挂载后，才把正确 USB 设备交给 WSL。
8. 再次核对 Linux 侧设备、分区 PARTUUID、容量、原签名及 Windows 侧记录，保存分区表和关键签名。验证备份盘仍在 Windows/DrvFS，且不是将要处理的设备。此时才允许格式化已授权的数据分区。
9. 创建 Btrfs `data` 子卷并恢复数据。恢复后对全部文件、目录、删除/重命名和内容哈希再核对；检查应用进程 UID、权限与挂载声明，不能仅以“复制完成”当作验收。
10. 应用配置中注册 Btrfs UUID、PARTUUID、分区容量、USB 实例与子卷路径；保留原逻辑备份身份，避免旧磁盘备份签名因代码路径改变而失效。生成新 Compose，重建应用绑定挂载，恢复原先保存的选择并等待实际就绪。
11. 更新并验证当前用户的低权限登录启动入口：先按 USB 实例接入，再由 Linux 按分区身份挂载。验证缺盘拒绝启动、完整停机卸载、再次接入与正常数据读写；不得重启共享 WSL/Docker 代替检查。
12. 外部迁移副本和旧云端历史继续保留，独立恢复及新备份链验收前不清理。

## 原生挂载边界

`nas_storage.py` 不包含格式化或修复功能。只有显式配置 driver=btrfs 才启用原生适配；未知 driver 拒绝回退。使用 UUID、PARTUUID、分区容量和实际挂载源共同验证，不按 /dev/sdX 字母猜盘，也不以可修改标签代替身份。

启动时只能挂载正确且已存在的 Btrfs 分区，挂载点必须为空；挂载失败不允许 Docker 创建空目录继续写。读写启动拒绝只读文件系统，正常卸载不使用 force/lazy。只在所有 NAS 服务停止并释放数据绑定后卸载数据卷。数据库挂载与数据卷分别验证，状态页和容量保护读取实际数据卷而不是代码盘。

Windows `attach-native-storage.ps1` 不安装驱动、不提权、不共享新设备、不格式化，只接入配置中已共享的 USB 实例；物理重插后按实例重新查询 bus ID。未准备 USBIPD 或未发现正确分区时拒绝启动。

## 当前备份不会因换文件系统自动升级

原生 Btrfs 迁移与下一代云端增量流是两项工作。现有在线 Restic 备份可继续从新数据路径读取，但每轮全目录扫描及历史校验的成本不会自动消失。分片 send 流、云端提交、断点续传、依赖链与独立恢复仍须按 STORAGE-ARCHITECTURE-EVALUATION.md 单独验收；不能把成功挂载 Btrfs 描述为“实时备份已完成”。

## 回退原则

格式化前任何验证不通过，就保持原 NTFS 和服务配置。格式化后若恢复或应用检查失败，保留外部可信副本和诊断结果，不重建无关磁盘；后续恢复必须从已验证数据开始。备份与迁移目录不可互相覆盖或自动清理。


## USB 存储驱动占用及挂载环境

普通共享后 attach 仍返回 Device busy 时，先完成所有最终备份、源数据未变与完整停机检查，再由管理员仅对已核验 SSD 执行 Windows 离线与独占 USBIPD 驱动绑定。此步骤不格式化、不处理备份盘；后续按 USB 实例查询 bus ID 并普通权限 attach。不得把 force bind 扩大为不校验身份的日常操作。

Windows 管理员启动的 WSL 进程可能看不到现有 Docker 命名空间中的外盘挂载。检查应通过 NAS 宿主入口进入 Docker 的挂载环境，同时核验 Windows 侧备份卷身份，不能因裸路径存在就假定备份盘在线。

跨介质恢复须验证文件内容、目录清单、UID/GID 和权限；共享历史恢复的暂存及发布必须处于同一文件系统和子卷，并确保同步进程能读取恢复副本。`verify-native-sync-recovery.py` 使用独立 Btrfs 夹具与模拟 API，覆盖跨盘原子发布、原文件/历史保留、实际 UID 读取及失败清理，不操作用户文件。
