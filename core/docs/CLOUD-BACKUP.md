# 网盘备份

首个接入的网盘是阿里云盘。管理台「备份 → 添加阿里云盘」生成二维码，在阿里云盘 App 中扫码确认后，窗口自动关闭并由服务器自动开始验证。验证按钮显示灰色及加载图标，刷新页面仍能取得任务状态；进程中断则允许重试。可手动重新验证。昵称、用户名和用户 ID 由账号接口读取，接口暂时不可用时保留已有信息或默认备注，不影响安全校验。只有上传、下载、SHA-256 校验及加密仓库检查通过，才允许执行备份。首次使用时，网盘中的 `GardenZero-Backup` 必须为空或不存在；遇到未知非空目录会拒绝使用，不清空已有内容。

## 数据方向与版本

NAS 是唯一备份来源。上传的是带 `COMPLETE` 标记、清单校验通过的一致性快照，包含用户数据、各应用的数据库逻辑导出及恢复所需的配置、代码和凭据，不上传正在运行的数据库镜像。手动「备份到网盘」先生成新的一致性快照；业务写入服务会按原有快照流程短暂停止并恢复。

Restic 在本地加密后，通过 rclone 的 WebDAV 后端与私有 OpenList 网关传输。工作容器只读挂载选定快照与凭据，网关没有 NAS 用户数据挂载。没有云端同步回本地的代码路径。用户自行修改或删除网盘内容不能改变 NAS，但可能导致远端仓库校验失败或丢失远端历史，不能承诺阻止网盘账户所有者在官方客户端删除文件。

增量上传复用已有数据块。失败时不把半成品记为成功，已提交的历史快照不删除；重试继续利用远端已有数据块。新快照中的删除不会出现在最新恢复视图里，旧快照仍保留旧文件。当前不提供云端自动清理或 `forget/prune` 操作，因此历史会持续占用空间。Restic 完整提交后还需仓库检查通过才记录成功。

当前自动网盘备份跟随每日一致性快照计划执行，另可手动发起；这不是实时文件同步。外接镜像盘离线不会阻止独立网盘目标执行。网盘失败后每五分钟检查是否可重试已有完整快照，不为重试再次停止业务；快照必须新于账号验证，以包含当前恢复配置。云端最后成功时间独立展示。尚未接入真实账户并完成首次上传、下载恢复验证前，不应把云端备份作为已验收的异地副本。

## 授权与运行文件

阿里云盘使用 OpenList 的 `AliyundriveOpen` 驱动。默认通过 `https://api.oplist.org.cn` 获取扫码授权及续期；该第三方服务参与令牌签发和续期，需要信任其运营方。令牌不返回浏览器、不写入 URL 或前端存储、不提交 Git；浏览器只收到短期二维码链接和本地不透明会话号。二维码、授权状态和令牌交换通过 NAS 直连，不配置代理回退。

- `system/secrets/cloud-bridge-token`：网关内部管理令牌。
- `system/secrets/cloud-authorization.json`：短期扫码会话，完成、取消或发现过期后删除。
- `system/secrets/cloud-webdav.json`、`cloud-rclone.conf`：各账号独立、限定备份目录的传输凭据；rclone obscure 不是静态加密。
- `system/secrets/backup-password`：Restic 仓库加密密码，必须另行保存离线恢复副本。失去它无法解密云端备份，包含在加密仓库里的密码副本不能解决这个启动依赖。
- `system/state/cloud-accounts.json`：不含令牌的账号元数据、验证状态及目录归属。
- `system/state/cloud-gateway/`：OpenList 的 SQLite 数据库与配置，可能含刷新令牌；完整配置备份使用 SQLite online backup 获取数据库副本。
- `system/state/cloud-backup.json`：最近备份结果。

OpenList 只发布本机 loopback 5244，不添加 Tailscale Serve/Funnel 路由。关闭默认访客，管理员使用随机强密码；每个账号有独立的受限 WebDAV 用户。网关归平台基础服务，在容器及日志页面查看，不新增首页业务应用。应用选择、用户原文件和已有备份不因配置网盘改变。

## 实现边界

账号管理、连接验证、受限 WebDAV 用户、加密增量备份、计划和状态展示由庭院共用实现。授权、刷新、驱动参数属于网盘提供方的适配层。115 将来可以复用前述共用层，但必须独立实现并验证它的 OAuth/扫码方式、权限、上传限制和 API 行为，不能只更换名称就宣称支持。

镜像由版本锁固定：OpenList、rclone 和 Restic；`core/services/cloud-backup.Dockerfile` 构建包含 Restic 与 rclone 的临时工作镜像。rclone 的普通 WebDAV 并非 Restic REST 后端，必须使用 `rclone:` 后端，不能直接把 WebDAV URL 填为 `rest:`。

准备新连接组件时先构建工作镜像并解析版本锁，运行 `prepare-cloud.py`、安装宿主脚本与 Compose、启动 `cloud-gateway`，完成内部账户加固后重建管理容器并等待实际就绪。不为配置网盘重启共享 Docker/WSL 或重新初始化现有实例。


## 账号任务与删除

卡片顶部可立即备份到全部云盘，每个账号也可独立发起备份。手动任务后台执行，先生成一次一致性快照，逐账号上传；一个目标失败仍继续其余目标。每账号独立保存最近成功时间、快照 ID、数据时间与最近失败结果；界面时间精确到秒，失败不覆盖上次成功时间。旧全局记录只有明确包含该账号时才迁移成功时间。

用户名旁的自动备份状态按钮为独立账号策略，关闭只影响后续自动任务，仍允许手动备份；已经执行的任务不会因切换而取消。每日准备快照和五分钟失败重试只选择已开启自动备份且通过验证的账号。

删除需要界面及后端明确确认，移除连接、受限 WebDAV 用户和当前传输凭据，保留远端仓库、恢复密码及已加密的历史。归属元数据保存在 system/state/cloud-removed-accounts.json，重新接管非空仓库仍需核验归属，不为方便而覆盖未知目标。

验证和备份事件写入 system/logs/cloud-events.jsonl。记录成功、失败及经过脱敏的命令错误输出，不记录令牌或上传内容；原始命令输出不会返回浏览器。历史未记录过的失败不能从后来的成功结果反推原因。
