# 网盘备份

首个接入的网盘是阿里云盘。管理台「备份 → 添加阿里云盘」生成二维码，在阿里云盘 App 中扫码确认后，窗口自动关闭并由服务器自动开始验证。后台检查时显示加载图标，刷新页面仍能取得任务状态；进程中断后自动重试。连接异常由后台自动检查并限频重试，网页不提供重新验证按钮。添加新账号和扫码授权不受其他账号上传或仓库校验阻塞；新账号连接验证等待生命周期独占锁，等待时仍显示验证中。同账号重新授权前先安全结束活动备份。昵称、用户名和用户 ID 由账号接口读取，接口暂时不可用时保留已有信息或默认备注，不影响安全校验。只有上传、下载、SHA-256 校验及加密仓库检查通过，才允许执行备份。首次使用时，网盘中的 `GardenZero-Backup` 必须为空或不存在；遇到未知非空目录会拒绝使用，不清空已有内容。

## 数据方向与版本

NAS 是唯一来源。所有已接入网盘共用变更收集、一致性恢复点、加密增量传输、校验和重试层；授权及具体驱动保留在提供方适配层。当前仍只验收阿里云盘接入，不宣称已有其他网盘驱动。

## 在线版本备份（当前模式）

网盘不再生成完整本地数据副本，也不停止应用。Restic 的只读 `/backup-set/data` 直接挂载活动 `data/`；临时 `/backup-set` 根目录仅含数据库导出、角色定义、配置包、清单和一个空 data 挂载点。空挂载点在宿主上始终无用户文件，子挂载只发生在临时容器内，不链接、不复制原始数据。数据库采用 pg_dump，SQLite 采用 online backup，禁止直接备份运行中的 PostgreSQL 镜像文件。

schema 5 / online-v1 清单标记 `consistency: eventual`。数据库导出是各自的事务一致视图，但与附件不是同一时刻；持续修改的文件可能变化或不可读。读文件错误、缺少数据库、未收到 Restic 完成摘要或仓库检查失败都不能冒充成功。每次成功形成一个可取回文件/数据库版本的恢复点，不承诺整套应用一键恢复。至少保留可用来源，整套业务恢复仍需隔离验证。

原始文件直接在线读取，Restic 仍按内容块去重、加密及保留云端历史。在线模式不使用 `--ignore-ctime`，避免遗漏保留大小/mtime 的原地改写。云端不执行 forget/prune；NAS 修改/删除只改变新版本的视图，旧版本保留，但不具备不可删除存储保障，不能阻止持有云盘删除权限的人或提供方删除仓库。

自动开关开启后，后台约每五分钟尝试一轮，任务结束后至少间隔五分钟，不重叠。失败按同样间隔重试；手动取消后延后 30 分钟，关闭对应自动开关可长期停止后续自动任务。依赖网关和数据库未就绪时暂缓，不自动启用用户关闭的服务。取消 API 不等待生命周期独占锁，只停止本任务命名的临时传输容器，不强杀数据库；临时元数据在成功、失败、取消后均回收。缓存位于容器受限 tmpfs，不建立宿主全量数据缓存。旧 `backup-settings.json` 的每日时间和时区不再驱动网盘任务，最长停写只保留供磁盘脚本兼容使用。

在线备份持生命周期共享锁，应用可以继续启停；磁盘备份、关机和卸载仍持独占锁。完整关机先取消当前在线任务再等待锁。小型元数据导出继续保留空间检查；去掉全量副本不等于可以绕过存储故障和低容量保护。

临时元数据目录为 `system/runtime/online-backup-<随机值>/`，仅包含已登记数据库和配置资源，不含 PostgreSQL 镜像或全量 data。新状态为 `state/cloud-online.json`、`cloud-online-auto.json`。历史记录保存在线/一致性模式；旧记录不补造模式。旧 schema 3/4 备份及其本地工作副本保留，旧恢复脚本不能直接声称支持 schema 5；恢复时将 Restic 点还原到新目录，`backup-set/data` 为文件，各 dump 与配置清单在顶层。严禁直接覆盖生产实例。


## 授权与运行文件

阿里云盘使用 OpenList 的 `AliyundriveOpen` 驱动。默认通过 `https://api.oplist.org.cn` 获取扫码授权及续期；该第三方服务参与令牌签发和续期，需要信任其运营方。令牌不返回浏览器、不写入 URL 或前端存储、不提交 Git；浏览器只收到短期二维码链接和本地不透明会话号。二维码、授权状态和令牌交换通过 NAS 直连，不配置代理回退。

- `system/secrets/cloud-bridge-token`：网关内部管理令牌。
- `system/secrets/cloud-authorization.json`：短期扫码会话，完成、取消或发现过期后删除。
- `system/secrets/cloud-webdav.json`、`cloud-rclone.conf`：各账号独立、限定备份目录的传输凭据；rclone obscure 不是静态加密。
- `system/secrets/backup-password`：Restic 仓库加密密码，必须另行保存离线恢复副本。失去它无法解密云端备份，包含在加密仓库里的密码副本不能解决这个启动依赖。
- `system/state/cloud-accounts.json`：不含令牌的账号元数据、验证状态及目录归属。
- `system/state/cloud-gateway/`：OpenList 的 SQLite 数据库与配置，可能含刷新令牌；完整配置备份使用 SQLite online backup 获取数据库副本。
- `system/state/cloud-backup.json`：最近备份结果。

OpenList 只发布本机 loopback 5244，不添加 Tailscale Serve/Funnel 路由。关闭默认访客，管理员使用随机强密码；每个账号有独立的受限 WebDAV 用户。网关归平台基础服务，在容器及日志页面查看，不新增首页业务应用。应用选择、用户原文件和已有备份不因配置网盘改变。

## 实现边界

账号管理、连接验证、受限 WebDAV 用户、加密增量备份、计划和状态展示由庭院共用实现。授权、刷新、驱动参数属于网盘提供方的适配层。115 将来可以复用前述共用层，但必须独立实现并验证它的 OAuth/扫码方式、权限、上传限制和 API 行为，不能只更换名称就宣称支持。

镜像由版本锁固定：OpenList、rclone 和 Restic；`core/services/cloud-backup.Dockerfile` 构建包含 Restic 与 rclone 的临时工作镜像。rclone 的普通 WebDAV 并非 Restic REST 后端，必须使用 `rclone:` 后端，不能直接把 WebDAV URL 填为 `rest:`。

准备新连接组件时先构建工作镜像并解析版本锁，运行 `prepare-cloud.py`、安装宿主脚本与 Compose、启动 `cloud-gateway`，完成内部账户加固后重建管理容器并等待实际就绪。不为配置网盘重启共享 Docker/WSL 或重新初始化现有实例。


## 账号任务与删除

网页仅通过账号自动开关管理周期性备份，不显示手动发起、停止按钮或「网盘列表」子标题；「添加阿里云盘」放在网盘备份标题行右侧。任务后台执行，先在线导出数据库和配置，再直接读取原始数据逐账号上传；一个目标失败仍继续其余目标。每账号独立保存最近成功时间、快照 ID、数据时间与最近失败结果；界面时间精确到秒，失败不覆盖上次成功时间。旧全局记录只有明确包含该账号时才迁移成功时间。

用户名旁的自动备份状态按钮为独立账号策略，关闭只影响后续自动任务；已经执行的任务不会因切换而取消。周期性在线备份和失败重试只选择已开启自动备份且通过验证的账号。

删除需要界面及后端明确确认，移除连接、受限 WebDAV 用户和当前传输凭据，保留远端仓库、恢复密码及已加密的历史。归属元数据保存在 system/state/cloud-removed-accounts.json，重新接管非空仓库仍需核验归属，不为方便而覆盖未知目标。

验证和备份事件写入 system/logs/cloud-events.jsonl。记录成功、失败及经过脱敏的命令错误输出，不记录令牌或上传内容；原始命令输出不会返回浏览器。历史未记录过的失败不能从后来的成功结果反推原因。


## 网页与历史

备份页只有「网盘备份」和「备份记录」两部分；网盘备份仅包含网盘列表与在线任务状态，不显示自动时间或停写配置。说明通过信息图标悬停/聚焦查看。网页记录表只展示脚本磁盘备份，按结果、目标筛选并分页显示；网盘历史仍在后台保存，账号区域展示实时状态及最近成功时间；失败详情、磁盘 UID/卷内路径和快照 ID 放展开区。账号删除不删除已有记录。磁盘备份改用 `bash core/scripts/disk-backup.sh [--purge-history]`，网页不再提供磁盘操作。

## 网盘读取并发与耗时

网关的回调下载通道限制为一条，Restic 经 rclone 的仓库请求统一使用 `-o rclone.connections=1`，让请求在客户端排队。不要只增加 HTTP 重试次数：超出网关短暂准入等待时可能返回 HTTP 416，rclone / Restic 会将其表现为数据块不存在；应先抽查原文件和哈希、降低并发后重新校验，不直接重建索引或删除历史。

在线备份的传输阶段包括读取云端快照和索引、扫描来源、去重及上传，不等于全程都在传输新增文件。页面只保留简短工作状态，具体步骤在本文说明；上一轮失败信息保留到后续成功，不能被下一轮自动重试覆盖隐藏。完整仓库校验仍实际执行，不因网络错误跳过或冒充成功。当前临时缓存随容器回收，每轮仍可能重新读取元数据，不宣称已实现逐文件即时提交。

## 自动检查与异常入口

备份失败后，任务释放生命周期锁，再自动检查连接和既有仓库身份；检查为只读，不重新初始化、修复仓库或删除历史。失败后至少间隔五分钟重试，刷新不会重复启动任务。新账号及扫码授权后的首次验证仍执行完整的上传/下载和仓库验证。

异常显示在网盘名旁的警告图标，支持悬停、键盘焦点和点击；点击进入扫码重新授权。已有账号正在备份时，先请求安全中断，再轮询等待并生成二维码，不在账号锁内等待任务退出。用户关闭授权窗口后停止轮询。网络、容量或仓库错误不会标注为已确认授权失效。页面移除独立的重新验证、重新授权按钮和实现步骤说明，只显示简短工作状态及最近成功时间。

备份期间删除按钮保持可用。用户二次确认后先关闭该账号自动任务，再请求安全结束正在运行的备份，待整个任务退出后解除连接；超时保留连接并允许重试，云端历史不删除。后台检查进行中仍等待检查完成后删除。

## 规模与业务影响目标（待实施）

用户要求：本地不保存完整第二份数据；备份不妨碍 NAS 正常业务；日常增量的主要工作量取决于变化量，不因存量文件和历史版本增长而每轮全量处理。网盘侧允许适量冗余和版本保留。

现状：每轮先完整扫描来源作安全检查，再由 Restic 处理全目录；数据库每轮完整在线导出，上传后再检查整个历史仓库，临时缓存不跨任务复用。因此当前流程会随文件、数据库和历史规模增加而变慢，尚不满足目标。

目标链路为：平台能力适配的变更追踪 → 持久化的元数据队列与合并 → 仅处理变化文件及相关索引 → 云端增量提交。元数据按需读取并设置容量预算；不把原始文件内容积压成本地第二份数据。完整校验和对账不放在每次提交的关键路径，并以低优先级执行。首次全量、漏通知补扫和恢复仍有规模成本，不宣传为绝对常数时间。

文件变化通知不可视为永不丢失：需验证当前挂载和各写入来源的覆盖，处理重启、断盘、通知溢出和日志缺口，再做低频对账。数据库导出也是实际数据，规模增长后须采用流式传输或有界缓冲，不在本地堆积完整导出或基线。数据库另设正式在线恢复链路，不将运行数据文件直接当成普通文件同步；变更日志若被采用，必须限制本地保留及断网积压，避免占满业务盘。

这不是已经部署的能力。降低 Restic 检查频率只能解决部分等待，仍须解决全目录扫描、仓库元数据读取、数据库全量导出与恢复目录维护，且通过固定增量、不同数据规模的验收。

低频写入、大存量下的下一代存储路线及隔离验证，见 [存储架构评估](STORAGE-ARCHITECTURE-EVALUATION.md)。该方案尚未替换当前在线备份实现，也未迁移生产数据。
