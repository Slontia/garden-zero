# 当前实例运维手册

本手册针对 Windows + WSL2 中当前实例，不构成新主机部署或跨架构认证。入口、账号文件和数据位置见仓库 README；不要把账号文件复制到聊天或公共仓库。

## 日常运行

Meta 查看磁盘、模块、备份及运行观察。Joplin 笔记与 Immich 共用 PostgreSQL，角色和数据库隔离；数据库现为基础服务，不随相册关闭。普通文件的 SMB/网页入口保持只读；上传照片通过 Immich，提交仓库通过 Git SSH。Syncthing 的 shared 完整同步已接入 Mac；Meta 支持网页绑定/解绑、进度、冲突查看和历史恢复副本。网盘接入、外接备份盘在线状态及最近成功时间以管理台为准。独占 SMB 写入已停用。

“应用就绪”表示服务健康，不代表设备配对、远端账户、长期负载或备份恢复全部验收通过。相册 ML 首次加载模型可能较慢；当前限制 3 GiB、单请求线程，空闲 120 秒卸载模型。大批量上传仍需观察内存及队列。

## 正常停止、弹盘和 WSL 重启

1. 保存客户端正在编辑的内容，停止上传、Git push 等写入操作。
2. 在 WSL 仓库目录执行 `bash stop.sh all`，等待返回成功。Meta 的“停止全部业务”保留远程和管理组件，不能作为弹盘完成标记。
3. 用 `findmnt /run/nas/database` 和 `sudo -n losetup -j <config.json 中的实际 image 路径>` 确认数据库已卸载、对应 loop 无残留；不要只检查默认旧文件名。
4. 在 Windows 使用安全弹出，完成后才拔 SSD。关闭/重启共享 WSL 也先执行完整停机，避免影响 NAS 正在写入的数据库。
5. SSD 重连后确认卷身份正确，再执行 `bash start.sh`。登录启动任务提供登录后的启动，不承诺无人登录或 Windows 睡眠期间可用。

命令失败时保留现场，不使用 `umount -f`、`umount -l`、kill 数据库或删除镜像来强制完成弹盘。

## 缺盘、掉盘和身份不匹配

- 检查 Windows 是否还能看到同一个 NAS SSD、盘符和 NTFS 卷身份。若卷消失，先停止业务写入并保存日志；不要创建同名空目录替代卷。
- 挂载与启停保护会校验实际卷 GUID、镜像 UUID、loop backing file 和挂载点。错误配置不能靠删除保护标记绕过。
- `C:\nas\system\state\deployment-blocked` 表示存储故障未解除；先查看同目录 incident/恢复记录，完成隔离恢复再解除。
- 原异常 postgres.img 仍保留，生产使用哪个镜像以本机 config.json 为准。只读 fsck 发现错误时保留原件，优先从已验证备份恢复到新镜像；不要对当前生产镜像运行自动修复。

## 服务或 Docker 故障

先从 Meta 看模块日志；页面不可用时在 WSL 执行：

```bash
bash core/scripts/host-command.sh status
bash core/scripts/host-command.sh logs immich
sudo -n systemctl status nas-agent.service nas-session.service --no-pager
sudo -n journalctl -u nas-agent.service -n 100 --no-pager
```

NAS 使用 `/usr/bin/docker --host unix:///var/run/docker.sock`，不依赖 Desktop context。共享 Docker 仍服务其他用途，不因 NAS 故障清空 Docker 数据或停止其他项目。主控制服务刚重启时状态接口可能短暂不可用，服务 active 后重新刷新；持续失败再排查控制 socket/凭据/模块日志。

## 容量不足

Meta 显示 SSD、数据库镜像内部和 C 盘备份空间。镜像逻辑容量 64 GiB，实际占用与空闲分开看。当前外层 SSD 低于 16 GiB，或镜像内部低于 1 GiB，调度器会停止业务，保留数据库挂载供检查；不是自动扩容或删除文件。

内置盘备份预计容量不足时拒绝新备份。保留 14 份是配置目标，自动清理尚未启用。先确认哪些备份已有独立可恢复副本，再人工制定清理；不要为了腾空间删除唯一原件或旧异常镜像。扩容需正常停机、可恢复备份及独立验证，不重新创建已有镜像。

## 备份与恢复

阿里云盘接入位于管理台备份页，扫码授权后需验证上传下载和加密仓库。共用传输层使用 OpenList + rclone + Restic，只上传 NAS 的只读一致性快照，不从云端回写；自动任务周期性在线执行，保留历史。完整边界、私有运行文件及恢复密码要求见 [网盘备份](CLOUD-BACKUP.md)。真实账号首次上传与恢复仍需接入后验收。

磁盘脚本仍会停写并生成一致性恢复点；Meta 的网盘立即备份改为在线导出数据库、直接读取原始文件，不停写。网盘自动任务不再使用每日计划，详见 CLOUD-BACKUP.md；磁盘冷备不自动运行；如果数据库已停止，记录为跳过而不冒充新成功。

以“最近成功”及“是否逾期”评估新鲜度，不用单纯文件修改时间。恢复验收见 [恢复说明](RESTORE-ACCEPTANCE.md)。本机独立恢复相册已通过小样本验收，网盘/HDD 与异机恢复未通过，所以继续保留手机/电脑的来源文件。

恢复演练目录含凭据和数据，保留在受保护的 C:\nas；不能上传报告整个目录。公开的验收 JSON 不含密码，但原始配置压缩包不可公开。

## 升级、换主机与安全访问

升级前先完成新的一致性备份及恢复检查，再在隔离副本验证目标版本、数据库迁移和客户端功能。生产使用固定版本/摘要，不直接拉取浮动 release；数据库迁移后不能仅换回旧镜像标签当作回退，应恢复配套数据库和内容副本。本轮未做版本升级。

换主机或携盘接续前完整停机；不得两台主机同时写同一镜像。记录架构、镜像摘要、UUID、目录、账号与网络身份，按单独计划验证。Windows 登录任务、systemd 与 Tailscale 身份不能假定在新机自动成立。

远程访问通过私人 Tailscale 网络，不启用 Funnel。应用认证和 Tailscale 访问策略分别验收；当前仅单管理员。完整账户策略和蜂窝网络条件尚未单独验收，不能把加入 tailnet 等同于按设备授权写入。

Windows 睡眠/休眠时 NAS 无法持续服务。接电自动睡眠/休眠超时目前为 0，但 Windows 日志仍记录过 Application API 睡眠请求；具体发起应用或操作未定位。连续观察遇间断会保留历史并重新计时，不把容器显示的运行时长作为 24 小时连续通过。

## 当前数据库位于内置盘

2026-11-18 起，活跃数据库镜像移到 C:\nas\system\databases\immich；SSD 上三份旧镜像只保留取证。用户文件仍在 SSD，断连时仍需停业务，但数据库不再依赖 USB 上的大型镜像文件。C 盘外层空间低于 16 GiB 也会拒绝新启动或停止业务。Windows 原生短测通过不等于 USB 链路长期稳定。

本机数据库备份与活跃数据库同盘，需要网盘/HDD 才能提供异盘保护。携盘前备份并验证数据库导出，新机从匹配版本恢复；不复用 SSD 上的旧故障镜像。不要对当前实例执行新初始化命令，默认初始化改为内置盘也不授权覆盖已有文件。


## 唯一写入设备（2026-11-19）

Meta 的“多设备文件访问”可以为一台在线设备授权 shared 写入。原 nas 共享和网页文件入口继续只读。写入地址是 `smb://<你的 NAS Tailscale 域名>:1446/shared`，使用原 SMB 专用凭据。每次切换先保存文件；切换会断开旧连接，未保存内容不自动合并。备份、控制服务重启、停止 SMB/远程模块及健康异常后撤权，需重新选择。完整实现与客户端待验收项见 [FILE-ACCESS.md](FILE-ACCESS.md)。

新增 `nas-file-writer` 是按需临时容器，不纳入 Compose 自动启动；无授权时不存在是正常状态。网关由 nas-agent 管理，loopback 1446；后端仅 loopback 1447，Serve TCP 1446 必须启用 PROXY v2，禁止 Funnel。正常停止/备份入口会回收写入后端。紧急情况下停止 nas-agent 会阻止远程写入；不要手动启动后端，也不要把后端端口公开。控制组件重启后仍显示撤销错误时，检查操作审计和容器退出码，不跳过退出 137 等保护去授予新设备。


## 当前普通文件模式：完整本地同步（2026-11-19 后续决定）

用户后续选择完整副本，此节覆盖上文唯一写入设备用法。独占 SMB 写入口已停用；现有只读 SMB/网页保留。通过 Meta 连接 Syncthing 设备并接受共享空间到 Mac 本地路径（建议 ~/NAS/共享）；离线可以读写，Tailscale 接通后再同步。私人 TCP 22000 传输，GUI/API 仍只监听本机。20 个收到的历史版本和无限冲突副本用于恢复，删除也会同步。具体接入、暂停、恢复和待验收项见 [FILE-ACCESS.md](FILE-ACCESS.md)。


## 同步进度与历史恢复

Meta“多设备文件访问”显示 NAS 已知进度和每台在线设备的已知进度；离线设备显示未知，不能据 NAS 空闲推断所有设备已收齐。连接后的 notSharing 表示设备尚未接受共享，paused 表示设备暂停共享。冲突入口提供双方只读下载；比较后在本机目录手动合并，不自动删除任何冲突副本。

“历史版本恢复 → 查看历史版本”列出收到覆盖/删除时保留的历史。点击“恢复为新副本”会创建 shared/Recovered-时间-随机编号/原相对路径，不替换当前文件，不消耗历史版本。NAS 共享恢复前自动暂停，完成后只恢复原本开启的同步；本来已暂停则保持暂停。副本会在同步开启后发送给其他已绑定设备。API Key 和 Syncthing 配置不会返回浏览器。

文件已清理、源链接、大小变化、路径越界、容量不足或存储保护时拒绝恢复。中途错误可能保持共享暂停，应先核实错误、现有 Recovered 文件和磁盘状态，再手动恢复同步。大文件恢复尚未负载验收，当前操作请求有超时；发生超时不要立即重复操作，先检查 Recovered 目录和操作审计是否已完成。所有恢复目前以新副本为准，不提供原位覆盖按钮。


## Tailscale 访问范围

当前 NAS 双栈只允许 Slontia@github 账号所属节点访问 TCP 80、443、445、2222、8443、8444、8445、22000；数据库、缓存、本机管理端口和旧 SMB 写入口不对 tailnet 放行。用同一账号加入的新设备自动纳入网络来源，但仍需各应用登录和 Syncthing 配对。其他账号需要另行授权。NAS 未开启 Tailscale SSH，Git SSH 使用 2222；其他设备的原 SSH 规则保留。

策略 NAS 主机别名绑定当前 IPv4/IPv6。删除/重新注册 NAS 节点造成地址变化时，必须同步更新两个别名；新建私有子网路由也需显式加入。不要重新添加通配 NAS 的全放行规则，否则会绕过限制。策略快照在 C:\nas\system\state\remote.json 的 access_policy 中，随配置备份归档；原策略与历次未通过提案保留在 host/state/tailscale-policy-*。本机生效检查见 tailnet-policy.json，实际跨账户设备拒绝仍待验收。


## 零号庭院服务状态恢复

网页登录和退出不启停服务。用户选择持久化到 C:\nas\system\state\desired-modules.json；systemd 正常退出使用 `nasctl.py shutdown` 保存选择，手动 `stop all` 表示主动停用业务。移除旧的“登录后自动启动”选项。目录权限按注册规则递归继承并在启动及状态查询时核对容器挂载，详见 [应用与目录权限](APPLICATIONS.md)。


## 独立磁盘镜像

配置独立卷的 nas-backup 后，通过 `bash core/scripts/disk-backup.sh` 手动发起，先完成一致性恢复点，再增量更新磁盘备份并同步删除。磁盘不加入每日计划，网页不提供发起入口。镜像结果独立展示，未知目标或外部修改会拒绝。布局、安全规则和恢复边界见 [增量镜像备份](MIRROR-BACKUP.md)。不要手工修改目标或删除隐藏事务记录。


## 启动完成标准

启动先等待所选容器 healthy，再实际访问管理台：检查 HTTP 服务身份、临时登录、完整首页、宿主状态查询、Docker 可用性、挂载权限及本次启用模块的 ready 状态。检查通过才返回成功，探针登录后会退出，不改变应用运行选择。Meta 链路最多等待 120 秒，超时返回非零错误。

Windows 登录入口即使发现 nas-session 已 active，也会再次执行只读的端到端就绪检查。手工检查可运行 `bash core/scripts/host-command.sh wait-ready`。该检查验证本机管理链路；外网 HTTPS 连通性仍需独立核验。


## 工作空间页面

应用 /apps、文件 /files、备份 /backups、容器 /containers、日志 /logs 独立导航。资源概览是 WSL 整体统计，运行时间用 HH:MM:SS；磁盘空间不在备份页重复展示。应用详情只列写入归属，Git SSH 授权状态和地址也在 Git 展开栏。所有已登记 NAS 服务按需获得 data 的只读授权，唯一写入与安全挂载核对继续生效。

见 [接入与恢复说明](JOPLIN.md)。`knowledge` 启动选择现在对应 `joplin` 容器；旧 Markdown 目录保留。不得再用只包含 `database.dump` 的旧流程宣称已恢复全部笔记；新快照还包含 `joplin.dump`、无密码角色定义及 `user-content.tar` 中的 Joplin 文件载荷。


## 统一登录

日常仅输入统一密码；管理台、文件浏览及相册使用 OIDC，笔记使用 SAML。身份服务归基础服务，数据与运行密钥在 system。数据库备份需包含 platform_auth。客户端首次授权、Joplin 原账户转换限制、应急入口、证书轮换及回退命令见 [单人统一登录](SINGLE-SIGN-ON.md)。统一退出不代表所有已授权客户端同时失效。


## 平台文件页面

网页浏览与下载位于 /files，复用管理登录，由 Meta 只读挂载 data。旧 files 容器退役；SMB 继续作为网络共享应用独立启停，旧 8443 入口仅重定向到管理台文件页面。应用选择中的旧 files 模块在读取时移除，smb 选择保留。


## 磁盘冷备与记录

磁盘备份仅通过 `bash core/scripts/disk-backup.sh` 发起，不由网页、每日计划或失败重试触发；网盘自动备份独立保留。备份页统一展示网盘和磁盘结果，支持方式、结果和目标筛选；UID、卷内路径、快照 ID 和错误折叠显示。每次外接磁盘任务的记录保存在 system/state/disk-backup-history，最近识别的卷名称保存在 hdd-volume.json。升级前只保存过最近一次结果，不能据此还原全部旧历史；保留现有记录，不补造数据。进程消失或接收中断信号时标记中断，只有完整成功才更新最近成功时间。

## Joplin 启动时钟校验

Joplin 会检查与 NTP 的时差，超过默认 2000 毫秒时拒绝启动。备份后的业务恢复遇到 Joplin unhealthy，应先检查其日志中的 time drift，并用 `chronyc tracking` 等只读工具确认时间来源，不把该问题误判为网盘授权失败。不通过设置 MAX_TIME_DRIFT=0 绕过数据安全校验。

先分别测量 Windows 与外部 NTP、WSL 与 Windows UTC 的偏差，区分宿主错误和 WSL 客体漂移，不能只看到 NTP 检查失败就要求重同步 Windows。`chronyc tracking` 还需区分公共 NTP 与 PHC 参考源，不能仅凭 PHC 显示零偏差认定对外准确。

WSL 中 chronyd 可能以 `-x` 只读模式运行，`chronyc makestep` 失败不代表 root 无权校正系统时钟。若 Windows 时间已经准确而 WSL 发生小幅漂移，可由 root 将 WSL CLOCK_REALTIME 对齐实测 Windows UTC，校正前限定合理偏差并计入测量延迟，再以 Joplin 的 NTP 检查和健康状态验收。仅在 Windows 自身偏差明确时才考虑管理员 `w32tm /resync`；不重启共享 WSL/Docker，不关闭 Joplin 时间保护。

## 相册客户端无法处理备份

先检查退出容器，而不仅看 `docker ps` 中的运行容器。PostgreSQL 当前 healthy 仍可能经历过 PANIC/自动恢复，Immich 可能在连接中断后退出；需要关联历史数据库日志、内核 I/O/内存错误和服务退出时间。`fsync: Cannot allocate memory` 不能只按登录问题处理，也不能据 rw 挂载推断没有存储错误。

发现数据库镜像写入错误时，先保存并校验新的完整逻辑备份，正常停止数据库消费者及 PostgreSQL，卸载后做只读文件系统检查；不得对生产镜像直接自动修复。检查通过后恢复原有应用选择，验证实际上传、原图下载哈希、测试资产清理及数据库落盘。检查通过与服务恢复不等于底层写盘异常已根治，保留事件证据继续评估复发风险。

## 常驻容器自动恢复

控制服务订阅 Docker 原生 `events` 流，只接收本 NAS Compose 项目的容器事件，忽略临时 one-off 容器。退出、删除、启动及健康变化会触发已保存选择的状态核对，空闲时不定时扫描容器。首次连接与断线重连会核对一次实际状态，以覆盖断线期间丢失的事件；断线每 5 秒重连，备份或应用操作占锁时也保留待处理恢复并延迟重试。失败退避通过独立截止时间唤醒，不依赖下一条 Docker 事件。原有存储与容量保护独立保留。容器异常退出、意外退出为 0 或丢失时，先检查卷身份、数据库受控挂载、空间、目录权限和依赖健康，再只拉起目标容器；不接管其他 Docker 项目，也不重跑临时备份/恢复容器。运行中但 unhealthy 的数据库不会被自动强杀重启。

不同应用启停、备份和关机继续通过生命周期锁互斥。主动停用应用会更新保存的选择，不会被守护重新开启；完整停止会持久暂停守护，下一次显式成功启动再恢复。直接 `docker stop` 不更新 NAS 意图，选中的服务会被视为意外停止；日常停用请使用 Meta 或 NAS 启停入口，排障维护需持有生命周期锁。

同一服务按 30、120、600 秒退避，30 分钟内最多尝试三次，之后等待冷却；连续健康 15 分钟清理重试预算，手动成功开启也会重置对应服务的预算。结果在 `system/state/container-recovery.json`，事件写入 `system/logs/operations.jsonl`，状态 API 包含 recovery 字段。

每次受控挂载在离线只读 fsck 成功后记录当前镜像的验证凭据。事件触发的恢复检查从该凭据对应的时间/内核日志游标继续检查当前 loop 设备；发现新的 I/O 错误、只读或日志中止时，进入存储保护，停止业务写入者与认证服务，并尝试正常关闭 PostgreSQL，保留镜像挂载供排查。关闭失败不强杀、不强制卸载、不修复原镜像。管理与远程连接仅在各自安全条件满足时保留恢复能力。

监听实现为 `core/scripts/nas_recovery.py`，随宿主安装脚本部署，由 nas-agent 运行；无需额外业务容器。源码、集成、测试和文档纳入 Git；监听状态、日志及凭据仍在被忽略的 system 运行目录。Compose 保持 `restart: no`，避免无条件重启绕过 NAS 维护与存储保护。

## WSL 盘符映射失效

若 Windows 能读 NAS SSD，但 WSL 返回 Invalid argument 或长期等待 p9_client_rpc，不据此认定物理盘数据损坏。先停止新写入、保留失败任务与上一份完整备份，用临时只读 drvfs 映射验证文件可读，并用 Windows mountvol/Get-Volume 核对配置中的卷 UID 和文件系统。确认仅旧映射失效后，在生命周期锁下刷新 WSL 盘符映射；检查普通 shell 与 dockerd 两个挂载命名空间，不假设二者共享映射。数据库镜像若在内置盘无需为此卸载、修复或重建。只在卷身份、空间及数据库挂载检查通过后，解除本次映射错误对应的保护并恢复原有应用；不要清掉其他存储故障的保护标记。


## 在线网盘任务与中断

网盘不提供每日时间、时区、最长停写设置；直接在线读取 data，数据库正规在线导出，任务不停止业务、不生成完整本地副本。每轮完成后至少间隔五分钟再自动尝试，正在运行时不重叠；停止本轮后延后自动重试 30 分钟。临时元数据目录在成功、失败和取消后回收。此模式标记为最终一致性，不承诺数据库和附件同一时刻。磁盘脚本保留原停写流程与内部停写保护。

`backup-operation.json` 绑定任务 ID 和进程身份，取消请求通过 `backup-cancel-<任务ID>.json` 传递，不删除生命周期锁。在线任务持共享锁，应用可并发启停；完整关机先取消任务，再持独占锁完成正常退出。原 `backup-settings.json`、`backup-daily.json` 不再驱动网盘自动任务；保留旧状态便于兼容和审计，不补造历史备份成功。

## 统一备份记录

`state/cloud-backup-history/` 按任务及云盘账号独立保存记录，覆盖预复制/导出失败、中断、单账号上传结果。移除云盘账号不删除历史，记录不保存令牌或账号完整配置。早期网盘结果仅从 `logs/cloud-events.jsonl` 已记录的单目标事件还原；无法确认的任务与时间不补造。新日志通过 history_id 与持久记录去重。磁盘仍使用 `state/disk-backup-history/`，在统一 API 中合并。页面每页 20 条，刷新保留筛选及已展开记录。


## 在线网盘备份取代每日停写计划

当前网盘使用 schema 5 在线版本备份，自动任务约五分钟一轮，不再使用每日时间、时区和最长停写配置，也不调用停写复制流程。业务应用不停止；数据库单独在线导出，原始 data 只读直传。`state/cloud-online.json` 记录在线准备阶段，临时元数据位于 runtime/online-backup-*，结束后回收；历史记录标记最终一致性，不能当作严格一致的应用恢复点。旧本地备份/工作副本需另行核验清理，不自动删除。网关/数据库关闭时自动任务暂缓，手动任务明确报错，不启用用户关闭的服务。停止本轮在线任务会延后自动重试 30 分钟。
