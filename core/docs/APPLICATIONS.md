# 零号庭院：应用、备份、容器与日志

## 四个独立页面

| 页面 | 地址 | 内容 |
| --- | --- | --- |
| 应用 | /apps，根地址 / 兼容 | 紧凑资源概览、应用启停、子功能、写入目录、共享绑定与 Git SSH 信息 |
| 备份 | /backups | 快照、镜像结果与历史、每日计划、网盘状态、保留或清理历史的显式选择 |
| 容器 | /containers | NAS 项目的容器、所属应用、资源、挂载、运行时间及日志入口 |
| 日志 | /logs | 选择应用，按来源标签切换日志 |

左侧导航只包含这四项，每项进行独立页面导航。原 /system 重定向到 /containers，根地址继续展示应用，兼容启动就绪探针与旧书签。

## 应用与功能

应用每项占完整一行；折叠时展示图标、名称、作用、状态和入口。展开显示子功能、写入目录及专有信息。操作列对齐，不支持的操作使用灰色按钮。运行状态本身是启停按钮，启停说明通过悬停或键盘焦点查看。刷新保留展开状态和共享绑定草稿。

| 应用 | 能力 | 对应容器 |
| --- | --- | --- |
| Immich 相册 | 照片与视频，独立智能检索开关，专属数据库容量 | immich-server、database、cache、immich-machine-learning |
| 文件浏览 | 网页下载与 SMB 只读挂载 | files、smb |
| 共享同步盘 | 完整副本、设备绑定、暂停、进度、冲突及历史恢复 | syncthing |
| 私人知识库 | Markdown 与附件阅读 | knowledge |
| Git 仓库 | SSH 授权状态、仓库地址、推送与拉取 | git |
| 基础服务 | 管理、认证与私人远程连接 | meta、tailscale |

相册关闭时智能检索不可单独启动，重新开启恢复保存的设置。前端操作逻辑应用与功能，不需要感知功能对应容器还是配置项。基础服务由主机维护，网页不允许停用，以免管理入口失联。

## 资源统计口径

应用页仅保留一块紧凑资源区域：运行时间用累计小时 HH:MM:SS（超过一天不重置小时），CPU 与内存使用细条，磁盘使用容量条；没有环形图、时钟或四张独立卡片。磁盘空间不在备份页重复展示。

- 运行时间来自 /proc/uptime，是 WSL/Linux 环境运行时间。
- CPU 来自 /proc/stat 的采样差值，对所有可见逻辑核心归一化，范围 0—100%。
- 内存已用为 MemTotal 减 MemAvailable，百分比以 WSL 可见内存为分母。
- CPU 与内存均包含同环境其他进程，不是 NAS 容器合计或 Windows 整机用量。
- 数据 SSD、本机快照盘和配置的镜像备份盘展示所在卷整体用量，包含其他文件。Windows 镜像卷可在 WSL 未挂载盘符时只读查询容量，并核对登记卷身份。
- 未知或失败显示未知，不伪造 0。相册数据库内部用量及稀疏镜像分配仍只放在相册展开栏。

WSL2 使用宿主 Windows 的物理 CPU 和内存；虚拟 CPU 由宿主调度，内存按需使用并受 .wslconfig 上限约束。上限不代表预先独占同等物理内存。项目不因界面调整修改 WSL 设置。

## 写入归属与读取

所有已登记 NAS 服务都允许按需只读访问 data；授权不代表每个第三方应用都会自动展示所有文件。容器按实际用途挂载目录，应用详情不逐项显示只读者。

唯一常规写入者继续由 core/templates/data-access.json 注册，递归继承：

| 路径 | 写入归属 |
| --- | --- |
| immich | immich-server |
| git | git |
| shared | syncthing |
| knowledge | 主机管理员 |
| 未登记路径 | 无应用写入者 |

详情只显示与应用相关的写入目录，省略 data/ 前缀。首页没有完整权限表或任意路径继承查询；后端继续检查实际 Compose 和 Docker 挂载，拒绝错误写入者、跨所有者的可写父目录、未登记读取服务和链接挂载。宿主机管理员不受容器规则限制。

共享客户端允许多设备编辑，由 Syncthing 统一维护 NAS 上 shared；历史恢复是持有生命周期锁且暂停共享后生成新副本的维护例外。

## 备份、容器与日志

备份页面保留 [镜像备份](MIRROR-BACKUP.md) 的事务、续传与历史保留规则，不在界面迁移中改变已有目标或历史。

容器表仅展示 NAS 项目，不返回环境变量或凭据。容器 CPU 按 Docker 单核百分比，可超过 100%；内存是即时工作集，与应用页的 WSL 整体统计口径不同。停止或采样失败时不显示虚构的 CPU、内存或运行时间。表格可按应用筛选、横向滚动。

日志选择应用后，通过标签切换聚合或单个来源。保留旧响应防串台机制和键盘导航，每个来源最近 100 行，总输出最多 64,000 字符。日志按纯文本呈现，未登录不可访问。

## 状态与验收

登录、退出、刷新或页面切换均不执行启停。运行选择保存在 system/state/desired-modules.json。更新前端只重建管理容器，沿用既有应用选择。

只读验证入口：tests/verify-meta-status.py（页面契约与实际 JavaScript）、tests/verify-meta-browser.ps1（独立 Chrome、桌面与手机布局）；协议级连接行为由 tests/verify-connect-js.py 验证。测试不依赖相册已开启，不自动启动业务服务。
