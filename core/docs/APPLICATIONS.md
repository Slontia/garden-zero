# 零号庭院：应用、备份、容器与日志

## 四个独立页面

| 页面 | 地址 | 内容 |
| --- | --- | --- |
| 应用 | /apps，根地址 / 兼容 | 紧凑资源概览、应用启停、子功能、写入目录、共享绑定与 Git SSH 信息 |
| 备份 | /backups | 快照、镜像结果与历史、每日计划、网盘状态、保留或清理历史的显式选择 |
| 容器 | /containers | NAS 项目的容器、所属应用、资源、挂载、运行时间及日志入口 |
| 日志 | /logs | 选择应用，按来源标签切换日志 |

左侧导航只包含这四项，每项进行独立页面导航。原 /system 重定向到 /containers，根地址继续展示应用，兼容启动就绪探针与旧书签。

## 应用与功能

应用每项占完整一行；折叠时展示图标、名称、作用、状态和入口。应用标题、稳定英文 ID 与存储图标在同一行，描述另起一行；折叠行不再显示路径名。有数据目录写权限的应用附文件图标，有业务数据库的应用附数据库图标；提示分别为“已使用数据目录”“已使用数据库”，支持悬停、键盘聚焦和 Escape 关闭，点击图标不会展开应用。展开显示子功能和专有信息。操作列对齐，不支持的操作使用灰色按钮。运行状态本身是启停按钮，启停说明通过悬停或键盘焦点查看。刷新保留展开状态和共享绑定草稿。不同应用可以并发启停；操作只锁定当前应用，同一应用的主服务与子功能不能同时变更。启停期间状态按钮显示加载动画，成功后直接呈现实际运行状态，不弹出保存成功提示；失败原因显示在对应应用内。功能开关以服务实际就绪为准，等待生效时显示加载图标，已保存的启用偏好不会提前点亮开关。备份、关机等维护操作继续与应用启停互斥。

| 应用 | 能力 | 对应容器 |
| --- | --- | --- |
| Immich 相册 | 照片与视频，独立智能检索开关 | immich-server、cache、immich-machine-learning |
| 文件浏览 | 网页下载与 SMB 只读挂载 | files、smb |
| 共享同步盘 | 完整副本、设备绑定、暂停、进度、冲突及历史恢复 | syncthing |
| Joplin 笔记 | 离线客户端写作、标签与附件同步；网页管理账户 | joplin |
| Git 仓库 | SSH 授权状态、仓库地址、推送与拉取 | git |
| 基础服务 | 管理、私人远程连接与共享 PostgreSQL | meta、tailscale、database |

相册关闭时智能检索不可单独启动，重新开启恢复保存的设置。前端操作逻辑应用与功能，不需要感知功能对应容器还是配置项。基础服务由主机维护，网页不允许停用，以免管理入口失联。

## 资源统计口径

应用页仅保留一块紧凑资源区域。桌面运行时间与四组细柱图并列：CPU、内存、NAS 数据盘、本机存储盘；手机上四图为 2×2，运行时间单独一行。运行时间使用累计小时 HH:MM:SS，没有时钟。首页不查询或展示可拔插镜像盘容量，备份页也不重复展示磁盘空间。

- CPU、内存复合图：深色为 NAS 用量，浅色为宿主总占用，底色为资源上限。宿主总占用已经包含 NAS，不将两者相加。
- NAS 范围为项目标签对应的运行容器，以及 nas-agent、nas-session、nas-soak 控制服务。读取 cgroup v2 的层级计账，去重父子组，避免重复累计；不包含其他 Docker 项目。
- CPU 分项来自 cpu.stat 的 usage_usec 差值，用相同区间的 /proc/stat 全核心时间和 SC_CLK_TCK 换算为宿主容量百分比。组发生新增、退出或计数重置时重新采样；单核 Docker CPU 百分比不直接与宿主百分比混用。
- 复合内存统一计入缓存：NAS 使用 memory.current 汇总，宿主总占用使用 MemTotal−MemFree，上限为 MemTotal。MemTotal−MemAvailable 的传统工作负载估算仍保留为 API 辅助字段，不用它与含缓存的 NAS 计账直接叠加。
- WSL 部署仅读取 WSL 可见的 CPU 与内存上限，不读取 Windows 整机资源；普通 Linux 同样按宿主可见资源统计。
- NAS 数据盘及本机存储盘显示所在卷整体用量，包含其他文件。本机存储盘承载数据库、运行数据及本机快照，不代表专用备份分区。
- 采样失败显示未知，不伪造 NAS 用量为 0。分项与总量读取存在很短的采样时差，图层独立绘制，不能将两层宽度相加。
- 共享数据库文件系统与稀疏镜像用量放在资源概览的两列紧凑统计中，包含 Immich 与 Joplin；资源区域底部不重复展示统计口径文字。

计账参考：[Linux cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) 与 [/proc 统计](https://www.kernel.org/doc/html/latest/filesystems/proc.html)。

WSL2 使用宿主 Windows 的物理 CPU 和内存；虚拟 CPU 由宿主调度，内存按需使用并受 .wslconfig 上限约束。上限不代表预先独占同等物理内存。项目不因界面调整修改 WSL 设置。

## 写入归属与读取

所有已登记 NAS 服务都允许按需只读访问 data；授权不代表每个第三方应用都会自动展示所有文件。容器按实际用途挂载目录，应用详情不逐项显示只读者。

唯一常规写入者继续由 core/templates/data-access.json 注册，递归继承：

| 路径 | 写入归属 |
| --- | --- |
| immich | immich-server |
| git | git |
| shared | syncthing |
| joplin-legacy | 主机管理员（旧资料保留） |
| joplin | joplin |
| 未登记路径 | 无应用写入者 |

折叠行只显示应用 ID 和存储类型，具体写入归属继续由后端登记与核验。文件浏览只读挂载整个 data，不显示文件图标；基础服务不使用自己的业务库，不因托管 PostgreSQL 显示业务数据库图标。旧 Markdown 的 joplin-legacy 目录继续保留，由主机管理员维护；Joplin 独占写入 joplin 目录。首页不展示完整权限表，后端继续拒绝跨应用写入、未登记读取及链接挂载。

共享客户端允许多设备编辑，由 Syncthing 统一维护 NAS 上 shared；历史恢复是持有生命周期锁且暂停共享后生成新副本的维护例外。

## 备份、容器与日志

备份页面保留 [镜像备份](MIRROR-BACKUP.md) 的事务、续传与历史保留规则，不在界面迁移中改变已有目标或历史。

容器表仅展示 NAS 项目，不返回环境变量或凭据。容器 CPU 按 Docker 单核百分比，可超过 100%；内存是即时工作集，与应用页的 WSL 整体统计口径不同。停止或采样失败时不显示虚构的 CPU、内存或运行时间。表格可按应用筛选、横向滚动。

日志选择应用后，通过标签切换聚合或单个来源。保留旧响应防串台机制和键盘导航，每个来源最近 100 行，总输出最多 64,000 字符。日志按纯文本呈现，未登录不可访问。

## 状态与验收

登录、退出、刷新或页面切换均不执行启停。运行选择保存在 system/state/desired-modules.json。更新前端只重建管理容器，沿用既有应用选择。

只读验证入口：tests/verify-meta-status.py（页面契约与实际 JavaScript）、tests/verify-meta-browser.ps1（独立 Chrome、桌面与手机布局）；协议级连接行为由 tests/verify-connect-js.py 验证。测试不依赖相册已开启，不自动启动业务服务。

共享数据库的生命周期、账户隔离、备份及客户端配置见 [Joplin 与共享数据库](JOPLIN.md)。配置键 `knowledge` 保留兼容现有启动选择，实际对应容器为 `joplin`；不自动导入或删除旧 Markdown。

## 稳定应用 ID

| 应用 | ID | 应用管理的数据目录 | PostgreSQL 数据库 / 业务账户 |
| --- | --- | --- | --- |
| Immich 相册 | immich | immich | immich / immich |
| 文件浏览 | files | 无专属目录，只读引用全部数据 | 无 |
| 共享同步盘 | shared | shared | 无 |
| Joplin 笔记 | joplin | joplin；joplin-legacy 保留旧资料 | joplin / joplin |
| Git 仓库 | git | git | 无 |
| 基础服务 | platform | 无 | 无业务库，负责托管共享 PostgreSQL |

`storage.data` 和 `storage.database` 是后端应用资源声明，不根据运行状态或名称猜测，不因停止应用而丢失标识。数据目录标识只表示具有写权限，排除只读引用，数据库标识表示业务库使用，而不是提供数据库基础设施。

旧应用 ID `knowledge` 和 `syncthing` 分别作为 `joplin`、`shared` 的兼容别名；日志链接和展开书签兼容，操作归一化后取得同一把应用锁，不能绕过并发保护。持久化启动选择的内部模块键仍保留兼容，不要求与面向用户的应用 ID 相同。数据库内建 postgres 维护库、账户不重命名为业务 ID。

首页仅显示五个业务应用，隐藏 platform 卡片；后端仍保留受保护基础服务，容器归属和日志选择不变。无参数进入日志页默认选中 platform 的全部日志，指定 app 或 service 时优先使用链接参数。

资源概览不包含具体应用名称。数据库文件系统显示内部文件用量 / 总容量；数据库镜像显示稀疏镜像在本机磁盘的实际分配 / 容量上限。两项标题提供悬停与键盘提示，解释内部释放空间和镜像实际分配不一定同步减少。
